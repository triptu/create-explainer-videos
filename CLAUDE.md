# Explainers studio

Narrated, captioned explainer videos of blog posts and articles. Built with Remotion (React → MP4)
and Kokoro TTS (local, free), or Gemini TTS through OpenRouter for a more natural voice. **One shared toolchain; one folder per video.** Never scaffold a new
Node project for a new video. Use `npm run new` here.

Two formats: **classic** (slides: one component per scene, crossfades) and **story** (one continuous animated
world, a moving camera, Buddy the mascot, music and sound design; Kurzgesagt / 3Blue1Brown style). See "Story mode".

## Setup (first run)

Needs Node 20+ and `ffmpeg`/`ffprobe` on PATH (install them if missing, e.g. `brew install ffmpeg`).
Run `npm install`. `capture` also needs `npx playwright install chromium-headless-shell`. The Kokoro
voice model downloads on the first `tts` run. `videos/` is gitignored: the user's videos stay local.
Optional: for a more natural voice, copy `.env.example` to `.env` and add an OpenRouter key (see "Voices").
Story mode (animated, with music) needs that key too: its voices and Lyria music go through OpenRouter.

## Layout

```
lib/engine.tsx     timing engine: scenes ← narration durations, useAt("keyword") sync, captions, partial renders
lib/clip.tsx       recorded web visuals in a frame, with camera moves and callouts (makeClips)
lib/story.tsx      story mode: global timeline at("beat","kw"), camera + parallax layers, music/ambience cues, <Sfx>
lib/story-ui.tsx   story mode: motion helpers (pop/soft/lin/span) + StoryOverlay (captions with speaker chips, chapters)
lib/buddy.tsx        Buddy, the studio mascot: moods, poses, walk cycle, outfits (lib/sheet/ renders its model sheet)
scripts/           CLI. Every command takes a video slug (partial match ok: `intro` → intro-to-rust)
templates/default  classic starter copied by `npm run new`
templates/story    story-mode starter (`--template story`)
videos/<slug>/
  video.json       title, source URL, tts engine, voice, speed, speech (pronunciation regex map), timing
  narration.json   [{id, text}]: one paragraph per scene, in order
  vo.json          generated by tts: durations + cache hashes (don't hand-edit)
  index.tsx        scene list (id ↔ component, section label, title) + registerRoot
  ui.tsx           this video's theme: palette, fonts, Shell (header/title/captions), primitives
  scenes.tsx       one React component per scene (classic)
  world.tsx, s-*.tsx   the world and its stations (story)
  capture.mjs      optional: which page visuals to record
  clips.json       generated by capture: clip sizes
  public/vo, public/clips, public/music, public/sfx   generated audio / clips (gitignored)
  out/             renders (gitignored)
  stills/          review stills + sheet.png (gitignored)
```

## Commands

| | |
|---|---|
| `npm run new <slug> -- --source <url> [--template story]` | scaffold from a template |
| `npm run tts <video>` | narration → audio. Re-synthesizes only changed scenes (`--force` for all, `--voice`, `--speed`, `--tts`) |
| `npm run capture <video> [jobs…]` | record live visuals from the source page into public/clips |
| `npm run check <video>` | scenes ↔ narration ↔ audio, every `at("kw")` exists in its narration, types |
| `npm run stills <video> [ids…] [--at 0.8]` | one still per scene + `stills/sheet.png`. Read the sheet to review layout. `--at 0.2,0.6,0.95` = several per scene (use for story mode) |
| `npm run sound <video> [--only id] [--critique]` | story mode: sound-effect library → public/sfx, Lyria music cues from video.json "music" → public/music |
| `npm run sfx <dir> [names…]` | synthesize the sound-effect library into any folder (to audition) |
| `npm run listen <audio> ["question"]` | ask Gemini about an audio file: transcript by default, or critique a mix/cue/effect |
| `npm run render <video> [ids…] [--scale 0.5]` | full → `out/<slug>.mp4`; with ids → `out/preview.mp4` (just those scenes) |
| `npm run studio <video>` | live Remotion Studio for one video |
| `npm run clean [video] [--all]` | delete stills/previews (and renders with --all) |

Each video bundles in isolation (own entry + own public dir), so render time and bundle size don't
grow with the number of videos. Render a single scene while iterating; only do a full render at the end.

## Voices

- **Kokoro** (default): local and free. Voices like `"voice": "af_heart"`, `"speed": 1.1`.
- **Gemini 3.8 Flash TTS** (optional, paid per use): noticeably more natural. Put `OPENROUTER_API_KEY=…` in `.env`
  at the repo root (gitignored, see `.env.example`), then set in video.json:
  `"tts": "google/gemini-3.8-flash-tts", "voice": "Charon"`. Other good voices: `Kore` (firm), `Puck` (upbeat);
  OpenRouter lists all 30 under the model's `supported_voices`. Leave `speed` at 1: Gemini already paces naturally.
- Use Gemini when the user asks for a better or more natural voice, or when `.env` already has the key. Otherwise Kokoro.
- **Directing the voice (Gemini).** Gemini reads the text strictly as a transcript, so direction never goes in the
  words. video.json `"style"` is the narrator's persona, sent as the request's instructions. Describe a natural
  person and register, e.g. `"A warm, clear, conversational explainer talking to a smart friend. Natural pace and
  normal volume, relaxed and genuinely interested."` (a good default). Avoid theatrical mood words
  ("hushed", "dramatic", "whispering"): the model overacts them. A beat or line can add a momentary `"style":
  "a little skeptical"`. Inline, use only sparse vocal tags in angle brackets: `<short pause>`, `<long pause>`,
  `<breath>`, `<sigh>`, `<chuckle>`, `<laugh>`. Punctuation (`...`, `--`) also shapes pacing. Never use `[square]`
  tags with Gemini: it reads them aloud (tts converts a leading one into the line's style). tts transcribes lines
  with tags and retries if one was spoken.
- **Dialogue** (two voices, podcast-like; good for dense material): a narration entry can be
  `{"id": "x", "lines": [{"who": "host", "style": "curious", "text": "Wait, why?"}, {"who": "guide", "text": "…"}]}`
  with `"cast": {"host": {"voice": "Puck", "style": "<persona>"}, "guide": {"voice": "Charon", "style": "<persona>"}}`
  in video.json. Mix freely with plain `text` beats. The host voices the viewer's questions and doubts; the guide
  explains. Captions follow the speaker.
- tts also stores sync marks (so `at("kw")` lands on the spoken word) and a speech envelope for lip sync.
- Switching engines re-synthesizes every scene (the engine is part of the cache hash). One request per scene, so
  durations change: re-run `check` and `stills` after.

## Workflow for a new video

0. **Propose a direction and get it confirmed before building** (the /video skill covers how): audience and goal,
   format (classic or story), the central metaphor if any, voice (narrator or dialogue), length, tone.
1. **Read the source fully.** Start with the raw HTML (`curl -sL <url>`): full text, exact wording, and every
   img/video/SVG URL. Switch to Playwright when the page is client-rendered (the HTML is an empty shell), when
   you need to see figures (screenshots) or computed styles for the theme, when a visual animates, or when the site
   blocks plain requests. Don't work from WebFetch or search snippets: they summarize and drop figures and media.
2. `npm run new <slug> -- --source <url>`.
3. **Write narration.json in your own words**, about 15–25 s per scene. Write what should be *heard*:
   spell out letters where needed ("C I", "N V M E"). Fix stubborn words with `speech` in video.json.
   Add matching written forms to `prettify()` in ui.tsx so captions read "CI", "NVMe".
4. `npm run tts <slug>`. Durations drive everything, so do this before building scenes.
5. **Design the theme to match the source's brand** (colors, fonts, light/dark) in ui.tsx.
6. **Make it highly visual.** Show the source's own visuals as-is where they exist: record live
   animations with `capture`, or use screenshots and hero videos. Build custom animated diagrams for
   everything else. Avoid text-only slides; every scene should have something moving that explains
   the idea.
7. Build scenes in scenes.tsx and list them in index.tsx. Sync reveals to speech with `at("keyword")`.
   Keywords must be exact substrings of that scene's narration.
8. `npm run check` → `npm run stills` → read `stills/sheet.png`, fix overlaps → preview a few scenes
   with `render <slug> <ids> --scale 0.5` → full `render`.
9. Verify the output: duration, audio level (`ffmpeg -af volumedetect`, expect about -20 dB mean),
   and a contact sheet of frames sampled across the video. Say plainly that you haven't watched it end to end.

## Story mode

One continuous animated world instead of slides: a camera travels between stations, Buddy reacts, music and sound
effects carry the mood. Narration is still split into short beats (about 6–20 s) for TTS and captions.

Taste (what the user cares about):
- **Every video gets its own world**, designed from its metaphor. `templates/story` is a skeleton, and earlier videos are
  technique references, not looks to reuse. A way in:
  1. a **setting** the viewer could stand in, and a **light** that sets the mood (dusk, lamps, a lab glow);
  2. a few **recurring objects**, each meaning one thing all video (parcel = message, crate = merged summary,
     shelf = the view), drawn once in ui.tsx as a small kit;
  3. **stations** along a path, roughly one per chapter, and what Buddy wears and holds at each.
- **Metaphors carry intuition, not facts.** Name the real mechanism plainly. For technical audiences, show mechanisms as
  the real artifacts (actual text, the source's worked examples, verbatim prompts) rather than through props: a
  half-metaphor, half-mechanism explanation confuses experts and newcomers alike. Make the switch on screen
  (e.g. "drop the boxes: here's the actual text").
- **Buddy** is the studio's signature: the robot never changes, only its outfit and props. Restrained, specific
  emotions; both eyes always do the same thing (a lopsided lid reads as a creepy wink). With a narrator it reacts
  silently; in dialogue it's the host (see the /video skill).
- **Everything moves with the words.** Reveals land on the keyword, old elements fade when the next idea arrives, and
  no frame sits empty. Sound is quiet (effects around 0.2–0.45): a soft effect under most reveals, a whoosh on camera
  moves, a chirp when Buddy's mood changes, music ducked under the voice.
- **Framing:** keep the ground low in the frame and text above the caption band, and size text for the zoom it will be
  seen at.
- **Motion with physics** (adapted from Kit Langton's psychopomp `explainer-motion` skill):
  - *Energy has a source.* Every beat moves something from a source, along a path, to where it lands. Nothing lights
    up, flashes or moves without a cause the viewer can point to.
  - *Quiet at rest, one focal action.* Idle things are still; motion means something is happening. Establish the
    source, follow the signal, read the result, and keep the background still while the narrator explains.
  - *Light is local.* Glow comes from the moving thing and falls off with distance; an arrival lights where it lands,
    not the whole object. Keep color meaningful: one accent is the thing to follow, red is failure.
  - *Physical easing.* Travel uses minimum-jerk easing (`smootherstep`), not a habitual cubic in-out; camera moves
    settle like a damped spring; panels drift in with a small, damped overshoot and their content follows a beat later.
    Flashes attack instantly and decay slowly.
  - *Reaction follows contact.* A reply doesn't start before its request arrives; impacts land on the spoken word,
    with a quiet sound.
  - *Rhythm and continuity.* Stagger entrances about 120 ms apart. Transform rather than cut: the same object carries
    across beats, the camera flies into the thing that opens. To show a fix, show the broken behavior, rewind visibly,
    then replay the same moment resolving differently.

Map of the pieces (`templates/story/world.tsx` shows them wired together):
- `lib/story.tsx`: `defineStory`, `useStory()` → `at("beat", "keyword")` / `start` / `end` as global frames
  (validated by `check`), `useCamera(shots)` + `Stage` + `Layer depth` (parallax), `track`, `Sfx`, `useTalk(who)`
  (lip sync from the speech envelope tts stores), music/ambience cues and `dips` from video.json.
- `lib/story-ui.tsx`: `pop`/`soft`/`lin`/`span`, `travel`/`smootherstep` (minimum-jerk) and `StoryOverlay` (captions with speaker chips, chapter labels).
- `lib/buddy.tsx`: `<BuddyAt x y face={moodAt(f, [[frame, "curious"], …])} talk walk look arms wave hop turn emote outfit>`.
  Moods: neutral, happy, excited, curious, thinking, confused, worried, sad, surprised, determined, proud, skeptical,
  sleepy. Outfit slots: `hat`, `neck`, `back`, `face`, `hold` (+ `color`, `color2`); see the `Outfit` type.
  `lib/sheet` renders model sheets (`Moods`, `Outfits`, `Poses`) and a `Talk` lip-sync test.
- `npm run sound`: Lyria music per chapter (video.json `music`, `musicStyle`) plus the procedural effects library
  (names in `SFX`, scripts/sfx.mjs). Lyria drifts toward piano and sometimes adds vocals or drums; use `--critique`
  and regenerate what fights the voice.
- Put one Buddy in world.tsx with a position `track` across the video rather than one per station (copies pop and can
  double up on camera moves). Keep shared world coordinates in their own module so stations can import them.

Order of work: narration → `tts` → `sound -- --critique` → design the world → build stations one at a time with
`check` and `stills -- --at 0.2,0.6,0.95` → half-res render + contact sheet + `listen` critique of the mix → full render.

## Scene conventions

- 1920×1080 at 30 fps. Shell reserves the header and captions. The content area is **1720×760**,
  starting at top 200 when a scene has a `title`. Scenes without a title get the full frame (add your own top padding).
- `useAt()(kw, offset)` gives the frame when the narrator reaches `kw` (by character position).
  `useProgress(at)` springs from 0 to 1, `useRamp(a, b)` eases linearly, `useSceneFrames()` gives the narration length.
- `interpolate` input ranges must be strictly increasing. Derive staggered times so they can't
  cross, or the render throws.
- Recorded clips: `<Clip name top bottom from maxW maxH cam={[{at,s,x,y}]}>` with `<Callout at x y>`
  children (x/y are fractions of the clip). Crop away page controls and description text with `top`/`bottom` (native px).
  A clip slows down slightly if the narration outlasts it.

## Gotchas (learned the hard way)

- Kokoro must run from a file (`scripts/tts.mjs`). Its phonemizer crashes under `node -e`.
- OpenRouter's Gemini TTS only returns raw 24 kHz PCM (`response_format: "pcm"`); tts converts it, trims edge
  silence and applies the same loudnorm. Other OpenRouter speech models are untested.
- To check a Gemini clip without listening, send the mp3 to `google/gemini-3.8-flash` as `input_audio` and ask for a
  verbatim transcript; compare it with narration.json.
- Raw Kokoro output is quiet. tts applies loudnorm (I=-16), so don't skip it.
- CDP screencast ignores deviceScaleFactor. capture uses `html{zoom:2}` in a 2560px viewport for crisp 2× clips,
  locks window scroll (some visuals call scrollIntoView, which shifts the crop), and measures the element only after any `setup`
  interaction (layouts grow when you add replicas, etc.).
- Captions split on `[.!?:]` followed by whitespace, so "4.6" and "A.P.I." stay intact. Prettify before chunking.
- zsh doesn't word-split variables. Use bash arrays for ffmpeg input lists.
- `findLastIndex` needs lib ES2023 (already set in tsconfig).
- `check` assigns `at("…")` calls to the nearest *exported* component above them. Keep `useAt` inside the exported
  scene and pass frame numbers to non-exported helpers as props, or check reports keywords from the wrong scene.
- Screenshots embedded in a private-repo PR (`github.com/…/blob/<branch>/x.png?raw=true`) need auth: fetch
  `raw.githubusercontent.com/<owner>/<repo>/<branch>/<path>` with `-H "Authorization: token $(gh auth token)"`
  (the contents API may 404 on asset branches). Put the downloads in a `fetch-assets.sh` in the video folder,
  since `public/` is gitignored.
- Scenes that only fill the top half of the frame: wrap the layout in `<Fit s={1.15}>` (template ui.tsx). It lays
  out at 1720/s wide and scales up, so text grows too. Check that fixed-width rows still fit in 1720/s.
  Fit's box has no height: give the wrapped root `position: relative; width: 100%` (not `absolute; inset: 0`),
  and swap fixed column widths for `flex` ratios. Scenes laid out with absolute x/y coordinates can't be Fit-wrapped.
- PR videos: automated review comments (Codex, security bots) are often already fixed by later commits. Check
  each finding against the current diff before putting it in a "for reviewers" scene.
- A source page's own before/after videos don't need `capture`: download the mp4 into `public/clips/`, add
  `{w, h, secs}` to clips.json by hand, and use `<Clip … loop>` (short clips would otherwise play very slowly).

- Emoji don't render reliably in headless Chrome; draw icons as SVG.

## Disk hygiene

- If the repo lives in an iCloud-synced folder (e.g. ~/Documents), make `node_modules` a symlink to
  `node_modules.nosync` (iCloud skips `.nosync` names) so 1.4 GB of packages never uploads or gets evicted:
  `mkdir node_modules.nosync && ln -s node_modules.nosync node_modules && npm install`.
  Don't delete the symlink, and don't let `npm` replace it with a real folder.
- One `node_modules` here (~1.4 GB). The Kokoro model and Playwright browser are cached globally or in node_modules.
- capture writes frames to a temp dir and deletes them. Stills and previews are disposable (`npm run clean`).
